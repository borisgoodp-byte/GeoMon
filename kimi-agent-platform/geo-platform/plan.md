## 一、资料吸收结论（需求的事实基础）

### 1. 诊断报告模板（韩后报告 = 标准模板，8 段固定结构）
1. Hero：诊断对象 / 官网域名 / 所属行业 / 诊断日期
2. 01 综合健康度总览：仪表盘总分 + 等级徽章(A/B/C/D) + 四维分卡 + 综合结论（按 技术/页面/内容/实测 分段 + 核心判断）
3. 02 三平台官网可见度速览：DeepSeek/豆包/通义千问 × 决策词/场景词/对比词 九格表（🔴零引用 / 🟢被引用）
4. 03 四大维度评估画像：雷达图 + 四维逐条评语
5. 04–07 四维度明细：维度得分条 + 发现列表；每条发现 = 严重度徽章（严重/待优化/亮点）+ 标题 + 正文 + 业务影响
6. 08 优化方向与预期价值：固本 / 立信 / 扩声 / 占位 四方向卡 + 说明
7. 页脚：保密声明 + 编制单位（清蓝官网GEO项目组）

### 2. 评分准则 v3.0（唯一评分依据，可复算）
- 四维 18 项：技术底座 5 项、页面架构 5 项、内容生态 5 项、GEO可见度 3 项
- 子指标四档打分：20 优秀 / 15 良好 / 10 待提升 / 0 缺失，**禁止连续打分**
- 维度一至三 = 5 子项求和(0–100)；维度四 =（3 子项和 ÷ 60）× 100
- 综合健康度 = 技术×25% + 页面×20% + 内容×30% + 可见度×25%
- 等级：A ≥80 优秀 / B 65–79 良好 / C 45–64 待提升 / D <45 亟需优化
- 维度四逐词类按命中平台数定档：3/3→20，2/3→15，1/3→10，0/3→0
- 18 项指标与锚点：
  - 技术：①AI爬虫准入与抓取健康 ②正文可提取性 ③内容发现协议(sitemap/llms.txt) ④结构化数据覆盖度 ⑤结构化数据规范度与实体关联
  - 页面：①核心页面体系完备度 ②URL语义与目录层级 ③内链与面包屑 ④页面语义标签规范 ⑤页面主题唯一性与重复控制
  - 内容：①决策问题覆盖度 ②内容时效与作者署名 ③内容原创性与信息增量 ④内容可引用形态 ⑤白皮书与深度内容资产
  - 可见度：①决策词被引用 ②场景词被引用 ③对比词被引用

### 3. 引用率看板规划（监测模块口径）
- 判定等级：L2 来源命中（KPI 主口径：正文给官网地址/链接，或来源列表含官网页面）；L1 品牌提及（不计入、单列观察）；L0 未命中
- 判定四步：来源解析 → 域名归属（官网资产域含子域计入；品牌自有非官网单列；竞品域用于份额；平台自有域/百科排除）→ 页面归一（去追踪参数/fragment/www/m/默认文件名/尾斜杠）→ 命中分级
- 固定词池 10–20 词：品牌类/通用类/业务场景类各约 1/3，商定后**锁定**，变更须审批并记录断层；支持**可拓词**（扩展词，单独标记、不计 KPI 分母或单独标注）
- 监测平台：豆包 / DeepSeek / 通义千问（文心一言暂不纳入）
- 节奏：日粒度趋势/日历只做监控；达标判定以 6/12 个月考核节点单日实测为准（≥30% / ≥50%；达成率≥80% 即验收合格 → 实测 ≥24% / ≥40%）
- 报价 KPI 档（闭环资料）：初级 ≥20% / 中级 ≥30% / 高级 ≥40%
- 看板模块：核心 KPI 卡（引用呈现率/被引用页面数/被引用总次数/意向词覆盖率/KPI达成状态）+ 日趋势（双考核线）+ 引用率日历 + 三平台对比 + 词池命中分布 + 被引用页面 TOP10 + 平台×词类矩阵 + 竞品对标（扩展）
- 周报/月报/季报导出

### 4. 商业化闭环（平台化范围界定）
A 战略诊断（需产品化：域名输入即出诊断）→ B 官网重构（人效交付，平台只做排期与进度记录）→ C 内容运营（人效交付，同上）→ D 数据洞察（P0 急需平台化：监测看板）
→ 本平台覆盖：**诊断产品化 + 报价排期出具 + 词池锁定 + 引用监测看板 + 周期报告导出**

## 二、产品架构（两大模块 + 统一数据底座）

### 模块一：诊断与商务出具中心
1. 项目管理：客户/官网域名/行业/服务档（初级/中级/高级）/项目阶段(A/B/C/D)
2. 智能诊断：输入域名 → 后端抓取器自动检测（DNS/可达性/http→https 跳转、robots.txt、sitemap.xml、llms.txt、首页+抽样页源码：title/description/H1/canonical/alt/JSON-LD/正文可见字数/URL结构/面包屑/导航链接）→ 18 子指标机器建议分 + 证据摘要
3. 人工复核：18 项四档打分台（机器建议分可改、每项填证据与发现文案），维度四由实测录入联动定档
4. 报告生成：按韩后模板自动渲染完整诊断报告（预览 + 导出）
5. 报价单：按服务项与 KPI 档生成报价单
6. 排期表：按 A→B→C→D 四阶段 + 6/12 个月考核节点自动生成项目排期

### 模块二：引用监测与报告中心
1. 词池管理：建池（10–20 词/三类）→ 锁定 → 拓词 → 变更审批记录
2. 实测录入：日期 × 平台 × 词 → L2/L1/L0 + 被引用页面 URL + 快照/备注；URL 自动归一
3. 监测看板：KPI 卡 + 日趋势（双考核线）+ 引用率日历 + 三平台对比 + 词类命中分布 + 页面 TOP10 + 平台×词类矩阵
4. 考核判定：6/12 个月节点单日实测 → 达标判定（含 80% 达成率口径）
5. 周期报告：周报/月报/季报自动生成与导出

### 技术栈
- 前端：React + TypeScript + Tailwind + shadcn/ui + ECharts（沿用看板规划方案视觉体系：蓝白商务风）
- 后端：Hono + tRPC + Drizzle ORM + MySQL（backend-building-swarm 全栈组合）
- 抓取器：服务端 fetch + cheerio 解析（不可达时降级为人工评估入口）
- 演示数据：韩后诊断（20/50/20/0 → 综合 21·D级，完整发现文案按报告还原）+ 一个监测期 demo 客户

## 三、执行阶段（Stage-Gate）

- **Stage 1 设计契约**（Orchestrator 本人）：产出 `DESIGN_SPEC.md`——信息架构/页面清单、数据模型（表结构）、tRPC 路由契约、评分引擎规则、抓取器检测项→子指标映射表、排期/报价生成规则、演示数据规格。门禁：契约完整覆盖两大模块全部需求点。
- **Stage 2 工作区与脚手架**：加载 swarm-workspace + vibecoding-webapp-swarm，初始化仓库与 worktree 机制。
- **Stage 3 后端构建**：加载 backend-building-swarm，委派 coder 子代理实现 schema + 路由 + 抓取器 + 评分引擎 + 种子数据。
- **Stage 4 前端构建**：加载 webapp-building-swarm，按路由树拆分委派（诊断中心线 / 监测中心线），门禁：构建通过 + 页面按契约还原。
- **Stage 5 测试与集成**：verifier 子代理全流程验证（评分数学复算、韩后 demo 还原度、看板口径、导出），修复迭代。
- **Stage 6 交付**：website_version_manager build_version，输出版本卡。

## 四、并行与依赖
- Stage 1 是关键路径，必须先完成（所有子代理的唯一事实来源）
- Stage 3 与 Stage 4 的脚手架部分可并行启动；前端页面依赖后端契约（契约先行即可并行开发）
- 两条前端线（诊断/监测）通过 worktree 分支隔离，主代理合并
